# Surface GPIO command regression bench

Source: [`tb_bridge.sv`](tb_bridge.sv).

## Inputs and packed oracle

The 10 ns clock drives the real `surface_ps_bridge` with its default d3-Z graph.
`build/surface_sim_d3_z/cases.mem` must contain the 423-case corpus generated by
`python qec/surface/sim.py --distance 3 --basis z --shots 256`. Each 26-bit vector
is `{syndrome[23:0], error, prediction}`. The bench reads that corpus but executes
only the first 40 entries, not all 423.

## Transaction task and checks

`command` waits for a falling edge, flips the request toggle, packs
`{toggle, 3'b0, op[3:0], index[7:0], data[15:0]}`, then polls status acknowledgement
with a 500000-cycle bound. Every test shot loads word 0 (detectors 0..15), word 1
(detectors 16..23 plus padding), and issues decode. It requires result-present,
expected error/prediction and a nonzero cycle count.

The reset command must clear result-present; a subsequent all-zero decode must
succeed. Loading word index 255 must report error. A global 100000000 ns watchdog
bounds the whole bench. Identity opcode 4 and arbitrary graph shapes are not covered
here; those belong to graph-specific verification. The bench does not emulate PS
UART framing or real AXI bus timing: it directly drives the GPIO mailbox wires.

## Verification and related files

Run `make sim_surface` then `make sim_bridge` from root with Vivado tools on PATH.
The bridge target also exercises the repetition mailbox and checks PASS logs.
See [`../../rtl/common/surface_ps_bridge.sv`](../../rtl/common/surface_ps_bridge.sv),
[`tb_surface.sv`](tb_surface.sv), `sim.py`, and `qec/surface/verify_hardware.py`
(root-relative) for graph-specific generated benches.
