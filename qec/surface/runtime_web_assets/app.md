# Runtime editor and local shot playback

`app.js` is a dependency-free browser controller loaded by [index.html](index.md). It never imports a template registry: the textarea contains arbitrary detector-annotated Stim text, with physical dimension and observable count supplied by compilation.

On load, exactly one `/api/config` fetch populates the example and Software/FPGA source label without running simulation or touching serial. Only `#run` sends POST `/api/run` with circuit, optional reference, integer-valued seed and added_noise settings. The browser rejects empty numeric fields, unsafe/noninteger/negative seeds and nonfinite/out-of-range depolarization before fetching. The server independently validates the same numeric limits. Run is disabled during a request. Server errors are displayed in the status live region, with playback and prior evidence cleared.

`invalidate` increments a revision, cancels the playback timer and drops the prior shot/evidence immediately on circuit, reference, seed or noise input. A completed request is ignored if its captured revision no longer matches, so edits during a run cannot resurrect stale data. Playback speed changes stop playback but do not invalidate a completed shot.

`drawCircuit` builds a real SVG timeline from each trace frame’s typed Stim `diagram` targets. H/S and measurement/reset gates are labeled boxes; CX/CY/CZ use distinct control dots and target circles. Other two-qubit gates retain their actual names and ordered endpoints. Consecutive target pairs and MPP/SPP products occupy distinct columns; product basis labels and dashed connectors preserve the actual operation without a fake CX decomposition. Hover titles preserve exact Stim text. QUBIT_COORDS is not interpreted as a device lattice; detector/observable annotations stay separate from qubit wires.

The diagram renders sorted **used** qubit indices, not every index below the maximum. Sparse q0/q1023 uses two wires/chips. Rendering is bounded to 64 used wires, a moving 16-tick window, and 32 source instructions per tick. Notices explicitly name omitted used-wire ranges/counts, omitted tick ranges, and omitted instruction ranges; an instruction touching an omitted wire is not partially drawn. The full active operation text remains in a collapsed disclosure. The diagram scrolls horizontally/vertically within a 430px-high region; timer/scrub changes bring the active TICK into view. Actual sampled Pauli labels retain X/Y/Z colors, independently of the highlighted tick.

`render` reads one immutable trace frame. It shows current actual Stim operations, sampled physical Pauli flips and cumulative detector events; final prediction/truth is displayed only at the last circuit tick. These frames are not a physical correction. The final mask comparison uses exact JavaScript Numbers, not bitwise operators, preserving bit 31 (2147483648) and all uint32 masks. `textContent` is used for source/evidence rendering, not HTML injection.

Replay starts at the current tick, or restarts from zero when already at the end. Pause stops the interval, Step advances one tick while paused, and scrub input pauses and selects a frame. None of these paths fetches anything. Speed is a local timer interval, not FPGA timing. One-frame shots remain valid even without a visible progression.

Circuit, graph and wire evidence remain collapsed by default. The wire view uses actual API transactions; in Software mode it explicitly contains an empty transaction list and no board identity. Schema errors tell the user to restart a mismatched server rather than silently fabricate frames.

Verify with `RUNTIME_WEB_URL=http://127.0.0.1:18767 node qec/tests/test_runtime_web_ui.cjs` from the repository root against a Software-only preview. The test drives initial Run, changing active gates, pause/step/scrub/end replay, invalidation, errors, unsigned bit31 and request counters.
